## 📝 Key Learnings

### Foundation Compliance is Critical
- All tools must follow mandatory HTML structure
- Foundation classes must be used (never duplicate)
- CSS variables must be used (never hardcode values)
- Responsive design handled by foundation (no custom breakpoints)

### Common Failure Patterns
1. **Missing Closing Tags**: Always balance opening/closing divs
2. **Wrong Meta Source**: Build uses `seo.metaDescription`, not `description`
3. **Button Classes**: All buttons need `.btn` base class
4. **Heading Hierarchy**: Main sections should be H2, not H3
5. **Structure Nesting**: `.seo-content` must be inside `.tool-interface`

### Test Workflow Best Practices
- ✅ Use `--reporter=list` for clean terminal output
- ✅ Test one tool at a time with `--grep` flag
- ✅ User runs dev server in separate terminal
- ✅ Rebuild after every code change
- ✅ Check div balance with PowerShell script

## 🔍 Debugging Commands

### Test Single Tool
```powershell
npx playwright test tests/foundation.spec.js --grep="tool-slug" --reporter=list
```

### Check Div Balance
```powershell
$content = Get-Content src\tools\tool-slug\index.js -Raw
if($content -match '(?s)export function render\(\) \{.*?return `(.*?)`;\s*\}') {
  $renderContent = $matches[1]
  $openCount = ([regex]::Matches($renderContent, '<div')).Count
  $closeCount = ([regex]::Matches($renderContent, '</div>')).Count
  Write-Host "Opening: $openCount, Closing: $closeCount"
}
```

### Check Meta Description Length
```powershell
$registry = Get-Content src\tool-registry.json | ConvertFrom-Json
$tool = $registry | Where-Object { $_.slug -eq 'tool-slug' }
Write-Host "Description: $($tool.seo.metaDescription.Length) chars"
```
